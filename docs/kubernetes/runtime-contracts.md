# Kubernetes runtime contracts

The compute route requires `SPRING_PROFILES_ACTIVE=aws,eks`. Activating `eks` alone fails before application clients are created; the original AWS S3, TLS, JWT and seed guards remain active. `kubernetes-local` is exclusively a disposable test profile. Runtime API uses Flyway disabled, Hibernate `validate`, no demo seed, and a per-replica bounded Hikari pool. A broker outage may defer the PostgreSQL outbox while accepted uploads remain durable; it does not invalidate API process liveness.

## Finite migration

The same API image executes `/app/migrate.sh`, which invokes `java -jar /app/app.jar --migrate-only`. The branch occurs before SpringApplication: no HTTP server, seed, scheduled task, queue or normal application storage client is created. Required dedicated variables are `MIGRATOR_DATABASE_URL`, `MIGRATOR_DATABASE_USERNAME`, `MIGRATOR_DATABASE_PASSWORD`, supplied through their explicit `_FILE` equivalents. No runtime credential fallback exists. It calls Flyway migrate then validate, clean is disabled, success exits 0, any exception exits nonzero. Kubernetes adds an active deadline and bounded retry; deployment waits for the new Job, saves logs on both outcomes and stops before changing application releases on failure.

AWS migrator JDBC URLs must contain literal unique `sslmode=verify-full` and `sslrootcert=/app/certs/global-bundle.pem`; security parameter case variants, percent-encoded names, duplicates and custom TLS factories/verifiers are rejected. The RDS public CA bundle in the image is a trust anchor, not a signing private key. Initially bootstrap pgvector and grant schema ownership using an independently controlled administrator session; API/workers receive business DML, migrator schema DDL. Migrations use expand-contract; Helm rollback never rolls back schema.

## API lifecycle and sockets

`/livez` contains Spring liveness state only. `/readyz` contains readiness state and a bounded database check; management/Prometheus is separately reachable inside the Pod on 9091. HTTP startup probe covers JVM startup before liveness begins. On SIGTERM Spring refuses new HTTP traffic and allows up to 30 seconds for active requests. Existing team sockets close with code 1012; clients request a fresh 60-second team ticket for every reconnect and refresh the committed team library over REST. All replicas must use the same JWT secret version. Rabbit fanout events remain best effort, and membership/account authorization is rechecked at handshake, every event and heartbeat. Rotation requires one coordinated secret-version rollout because signing-key overlap is not implemented. An optional dev-only `APP_EXPOSE_INSTANCE_ID=true` exposes the actual Pod UID and full release SHA in response headers for public-ingress distribution evidence; it is disabled by default and rejected outside EKS dev.

ALB deregistration, propagation/preStop delay and application shutdown all consume the same Pod grace budget. The initial chart uses API 90 seconds (15 preStop + 30 application shutdown + 30 target deregistration + 15 margin) and workers 150 seconds (100 absolute drain + 50 margin). These are initial budgets; tune against observed task and endpoint times, never add preStop time outside this budget. ALB only targets business 8080 and `/readyz`; no public route exposes 9091, encoder or workers.

## Publication and worker fencing

V5 adds an outbox publication token and 45-second lease. Each dispatcher claims exactly one due row with `FOR UPDATE SKIP LOCKED` in a short atomic SQL statement, releases database locks, and then performs broker publication/confirmation. Confirmation writeback and release require the same claim token; status and attempt checks prevent erasing a faster worker's retry/DLQ request. Killed publication leases expire. A crash after broker ACK but before database writeback may duplicate a message, so delivery remains at least once. The real PostgreSQL concurrent-scheduler tests verify disjoint claims, expiration, broker-failure recovery and stale-owner rejection.

Workers maintain a renewable token-fenced lease on their stable RDS session while holding the per-media advisory lock. Renewal and lifecycle transactions use one serialized session so renewal cannot commit another thread's partial work. Connection or claim loss aborts subsequent writes. Attempts write to immutable claim-specific object keys to prevent a stale in-flight PUT overwriting a newer successful variant. A durable object-attempt registry and periodic garbage collection remove unreferenced superseded prefixes, protect active claims and referenced variants, and repeat cleanup to catch late accepted S3 writes. An already accepted external S3 request cannot be atomically cancelled by a DB failure; eventual tombstone/attempt reconciliation is part of the contract.

SIGTERM cancels subscription, uses manual ACK and the bounded drain interval, and leaves unconfirmed work recoverable. Worker `/livez` equivalent is `python -m app.health --mode live`: process/main-loop heartbeat only. `--mode readiness` checks bounded MQ/DB health. Readiness does not itself stop Rabbit delivery; consumer code owns pause, cancellation and reconnect. DB/MQ outage must lower readiness without a restart storm. Do not place these stable session advisory locks behind transaction-pooling proxies.

Hosted fault tests may enable a guarded filesystem barrier after actual S3 variant writes. It requires MinIO, an explicitly disposable environment and local/kubernetes-local test mode, has a finite 900-second maximum and checks the original lease every second. Any test-hook configuration in AWS mode is rejected. The marker records the actual job/claim/session; it cannot execute arbitrary code. This enables real elapsed long-task, active shutdown and post-storage DB-session loss tests without shipping an AWS fault path.

## Encoder, identity and files

Encoder exposes process `/livez` and `/readyz` returning 503 until model loading, fixed-version validation and minimal warmup complete. Business encoding requires the shared nonempty token and matching model version. CPU ML is optional; base media works without it. Each Pod uses its own writable cache; no cross-AZ RWO cache is required. Real inference initialization verifies mechanics, while retrieval quality still requires a fixed corpus/query dataset and complete scored evidence.

Images run as nonroot. Helm enables read-only rootfs, drops capabilities and supplies writable bounded `/tmp` and per-Pod model cache. Java defaults heap to 65 percent of container memory, leaving native/agent overhead; configure resource requests/limits against measurements. nginx uses port 8080 and temporary files under `/tmp`. Startup scripts read only explicit whitelisted `_FILE` references; missing, empty or conflicting file/direct values fail without printing secrets. Secret rotation is adopted via coordinated restart, not inferred from CSI file updates. Each workload has a separate Pod Identity/Secret allowlist; encoder gets no S3 permission and migrator cannot use administrator secrets.

## Evidence boundaries

Unit tests include a virtual task longer than the original five-minute lease and fencing failure boundaries. PostgreSQL tests, hosted kind tests and browser/CLIP runs provide their own artifacts. They do not validate EKS Pod Identity, ALB/ACM, CloudFront, RDS/MQ managed-service TLS, private runner reachability or production availability. Record those independently in the AWS acceptance matrix with cluster, namespace, Pod UID, imageID, SHA, raw denominators and failures.
